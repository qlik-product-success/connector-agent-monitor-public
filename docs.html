Qlik Data Gateway Monitor

The Qlik Data Gateway Monitor, a.k.a. the ConnectorAgent Monitor, is a tool developed and maintained by Qlik Customer First Data Analytics (CF QDA).

Features

  • Monitors the Qlik Data Gateway - Direct Access Windows service process and restarts it if necessary ✅
  • Saves status endpoint responses for diagnostic purposes ✅
  • Provides an API for collecting all Direct Access Agent service logs ✅
    • DirectAccessAgent (DirectAccessAgent.log and DirectAccessAgent_YYYYMMDDHHmmss.log)
    • ConnectorAgent (connector-agent_logs_YYMMDD.txt)
    • ODBC Connector (odbc-connector_logs.txt and odbc-connector_logs_[data_port].txt)
    • SAP BW (QvSAPBwConnector-YYYYMMDD_HHmmssfff-[data_port].log)
    • SAP SQL (QvSAPSqlConnector-YYYYMMDD_HHmmssfff-[data_port].log)
    • SAP Package / ODP (QvSapConnectorPackage-[data_port].log)
    • File Connector (file-connector_logs_YYMMDD.txt)
    • REST Connector (rest-connector_logs.txt)
  • Collects Windows Application and System event logs covering the specified time period ✅
  • Includes copies of the gateway and Monitor configuration files (secrets redacted) and system information in every log package ✅
    • OS, hardware and installed .NET runtimes, gateway component versions, ODBC drivers, environment variables and TCP connections (see Log Package Contents)
  • Checks the ports configured for the gateway for conflicts with other processes, Windows excluded port ranges and each other ✅
  • Optionally schedules automatic collection and upload of logs to FileCloud, sending large packages in chunks ✅
  • Transforms gateway component logs into a single timeline that can be queried, or loaded into Qlik Cloud apps (see Querying Gateway Logs) ✅
  • Optionally configures Windows Error Reporting to save crash dumps of gateway processes (see Crash Dumps) ✅
  • Being considered for future releases
    • Save server health metrics
    • Web proxy support for automatic log upload to FileCloud
      • Please note: This feature is not available in the current version of the Monitor.
      • If you need this feature, or have another idea you would like to share regarding the Monitor, then please log it here and we will consider it for future releases.

System Requirements

  • Same as the Qlik Data Gateway - Direct Access 1.6.8 and above:
    • Windows Server 2016 or later
    • Setting up Qlik Data Gateway - Direct Access > System prerequisites
  • Install the Qlik Data Gateway - Direct Access before the Monitor. The gateway installs the .NET runtimes that the Monitor shares, so they do not need to be installed separately:
    • Monitor 1.0.0 and later run on .NET 10 and require Direct Access gateway 1.8.2 or later.
    • Earlier Monitor versions run on .NET 8, which is installed by earlier gateway versions. If the gateway cannot yet be upgraded to 1.8.2, use Monitor 0.10.0 or earlier.
    • As a safeguard, the Monitor 1.0.0+ installer checks that the .NET 10 and ASP.NET Core 10 runtimes (x64) are present and stops with a message, without changing anything on the server, if they are not (for example, with an older gateway).

Installing

  • Download the latest installer. This link always points to the newest release. Previous versions and their release notes are on the Releases page.
  • Make sure the Direct Access gateway is installed first (see System Requirements). This includes when upgrading the Monitor from a version before 1.0.0: upgrade the gateway to 1.8.2 or later first.
  • The Monitor can be installed on an active gateway without causing interruptions. Just download and run the installer. No restarts or manual Windows service starts are required.
    • For silent installs (/quiet), stop the DataGatewayMonitor Windows service before upgrading. Otherwise the installer can wait a long time for the service's files to be released.

What's Changed in the Latest Release

Changes since version 0.5.10. See the Releases page for the notes of each version.

  • Version 1.0.0 runs on .NET 10 instead of .NET 8 and requires Direct Access gateway 1.8.2 or later, which installs the .NET 10 runtimes. Nothing extra needs to be installed with the Monitor. The installer stops with a message if the runtimes are missing.
  • Log packages now include the gateway and Monitor configuration files, with secrets redacted, and system information such as OS, hardware, installed runtimes, gateway components, ODBC drivers, environment variables and TCP ports. See Log Package Contents.
  • Log packages now include a port conflict check of the ports configured in configuration.properties (Processed\PortConflicts.csv).
  • New /logs endpoint that returns all gateway component logs as one queryable timeline in JSON or CSV, which can be loaded into Qlik Cloud apps. See Querying Gateway Logs.
  • Windows Error Reporting crash dump collection for gateway processes can now be enabled through the Monitor's configuration. See Crash Dumps.
  • Large log packages are now uploaded to FileCloud in chunks (see ChunkSize in LogUploader).
  • The installer no longer shows a non-functional Options button.
  • Note: In-place upgrades from versions before 0.5.10 might be impacted by an issue that prevented the Monitor service from starting after installing Direct Access Gateway 1.7.4. If that happens, uninstall the Data Gateway Monitor and install the latest version. Previous settings will not be lost.

How It Works

  • The Monitor sends a request to the ConnectorAgent's status endpoint which triggers the agent to check itself and all of its registered connectors at the time of request.

  • The JSON payload of each response is logged to a C:\ProgramData\Qlik\Gateway\Monitor\Logs\connector-agent_status_YYYYMMDD.log file.

  • The statusCheckResult in that payload must be PASS.

  • The Monitor also waits for the ConnectorAgent.exe process to be running and that it returns at least one PASS (after the Monitor starts up) before any non-PASS is counted as a failure.

  • After the first failure, it checks for a PASS every minute (frequency is configurable via StatusMonitor.CheckInterval) for AGENT_HEALTH_FAIL_MINUTES_LIMIT + StatusMonitor.RestartThreshold minutes (5 + 2.5 = 7.5 minutes by default, also configurable) after which it kills the ConnectorAgent.exe process and attempts a restart of its associated Windows service.

  • The AGENT_HEALTH_FAIL_MINUTES_LIMIT value is read from the C:\ProgramData\Qlik\Gateway\configuration.properties file and the StatusMonitor settings are in, or can be added to the C:\ProgramData\Qlik\Gateway\Monitor\appsettings.json file.

Configuration

The configuration defaults work for most use cases. A default appsettings.json file is installed along with the tool. An environment-specific appsettings.json file can be created in the C:\ProgramData\Qlik\Gateway\Monitor folder. Some features, like automatic log upload, require either creating or merging settings into this file as shown in the next section. Changing any Monitor settings, other than the LogUploader settings, currently require restarting its Windows service.

Manual Log Collection

The Monitor can be used directly on the gateway server to collect logs and save them to a local folder via its API, or a web browser using the steps below.

  1. Open a modern browser, such as Chrome or Edge (Microsoft Edge comes preinstalled on recent server versions), and enter the following URL: http://localhost:5051/logs/download?start=YYYY-MM-DD[THH:mm:ss][+-HH:mm][&end=YYYY-MM-DD[THH:mm:ss][+-HH:mm]] where:
    • YYYY-MM-DD is the date from which you want to start collecting logs.
    • THH:mm:ss is the letter T followed by the time of day in 24-hour format from which you want to start collecting logs. This is optional.
    • +-HH:mm is the time zone offset (relative to UTC) for the data and/or time provided. If a time zone is not specified, then it is assumed to be UTC. This is optional.
    • It is recommended to specify the start date at least two (2) days before the period of interest to ensure all pertinent logs are included.
    • An optional end date can be specified in the same format as the start date. If not specified, then the current date and time plus 5 minutes is used.
  2. The browser should either save the logs as zip file to your Downloads folder, or prompt you to save the logs to a location of your choosing.
    • Depending on the length of time specified, the zip file may be large and take a while to start downloading.
    • The Direct Access gateway and Data Gateway Monitor both rotate component logs on a regular basis as needed.

Log Package Contents

In addition to the gateway, Monitor and dump files for the requested period, each log package (manual or automatic upload) contains:

  • Configuration\Gateway and Configuration\Monitor: the gateway's *.properties, *.txt and *.json files from C:\ProgramData\Qlik\Gateway, and the Monitor's appsettings*.json files from C:\ProgramData\Qlik\Gateway\Monitor. Values of settings whose names suggest a secret (for example, password, secret, token or API key) and credentials embedded in URLs are replaced with ***REDACTED***.
  • Processed\FileList.csv: every file considered for the package, and whether it was included and why not if it wasn't.
  • Processed\SystemInfo.csv: OS version, CPU count, memory, uptime, time zone and installed .NET and ASP.NET Core runtimes.
  • Processed\GatewayComponents.csv: the Direct Access gateway release and the file and product version of each component and connector.
  • Processed\OdbcDrivers.csv: installed 64-bit and 32-bit ODBC drivers and their versions.
  • Processed\EnvironmentVariables.csv: system, user and effective environment variables of the Monitor service, with secrets redacted as above.
  • Processed\TcpConnections.csv, Processed\TcpDynamicPorts.csv and Processed\TcpExcludedPortRanges.csv: TCPv4 connections and listeners with their owning processes, the dynamic (ephemeral) port range and excluded port ranges.
  • Processed\PortConflicts.csv: a check of every port and data port range configured in configuration.properties (for example AGENT_PORT, ODBC_PORT or ODBC_DATA_PORT_RANGE_START). It reports a Conflict when a port is used by a non-gateway process, reserved by a Windows excluded port range or configured for more than one setting, and a Warning when non-gateway processes are using ports in a data port range within the dynamic port range. Data port ranges are assumed to span 10 ports.
  • Processed\WindowsEventLog.csv: Windows events for the requested period.
  • Processed\GatewayLogEvents.csv (optional): the events of all gateway component logs for the requested period, all levels, merged into a single timeline with the same fields as the /logs endpoint. This is not included by default. To include it, set LogCollector.CollectStructuredLogs to true, or add &structured=true to the /logs/download URL (&structured=false excludes it even if the setting is true).

Configuration files and system information can be excluded by setting LogCollector.CollectConfigurationFiles or LogCollector.CollectSystemInfo to false.

Querying Gateway Logs

The Monitor's /logs endpoint returns the events of all gateway component logs as a single timeline, ordered by time, with multi-line entries (for example, stack traces) merged into one event. Results can be filtered and paged, and are returned as JSON (default) or CSV. This makes it possible to load gateway logs directly into a Qlik Cloud app through the Direct Access gateway's REST connector, or to view them in a browser on the gateway server.

http://localhost:5051/logs?start=YYYY-MM-DD[THH:mm:ss][+-HH:mm][&parameter=value...]

ParameterDescription
startRequired. Start of the period, in the same format as /logs/download. If a time zone is not specified, then it is assumed to be UTC. In a URL, write a + time zone offset as %2B, for example +02:00 as %2B02:00.
endEnd of the period (exclusive). If not specified, then the current date and time plus 5 minutes is used.
componentComma-separated list of components, for example ConnectorAgent,ODBC. Not case-sensitive. All components are included if not specified.
levelMinimum level: Trace, Debug, Info, Warn, Error or Fatal. For example, level=Warn returns Warn, Error and Fatal events.
reloadIdOnly events for this reload ID (exact match, not case-sensitive).
appIdOnly events for this app ID (exact match, not case-sensitive).
searchOnly events whose message contains this text (not case-sensitive).
offsetNumber of matching events to skip. Defaults to 0.
limitMaximum number of events to return, from 1 to 100000. Defaults to 10000.
formatjson (default) returns an array of objects. csv returns comma-separated values with a header row.

Invalid parameters return HTTP status 400 with a message describing the problem. Examples:

  • http://localhost:5051/logs?start=2026-09-29 returns the first 10,000 events since midnight UTC on September 29, 2026.
  • http://localhost:5051/logs?start=2026-09-29T08:00:00-05:00&end=2026-09-29T10:00:00-05:00&level=Warn returns warnings and errors between 8 and 10 AM US Central Daylight Time.
  • http://localhost:5051/logs?start=2026-09-29&component=ConnectorAgent,ODBC&search=timeout&format=csv returns ConnectorAgent and ODBC connector events that mention "timeout" as CSV.
  • http://localhost:5051/logs?start=2026-09-29&reloadId=6c1e...&offset=10000&limit=10000 returns the second page of 10,000 events for a reload.

Each event has the following fields. Fields that don't apply to a component's log format are empty (null in JSON).

FieldDescription
eventTimeUtcTime of the event in UTC, for example 2026-09-29T14:05:09.123Z.
componentGateway component that wrote the event, for example DirectAccessAgent, ConnectorAgent, DCaaS, ODBC, REST, File, SAPBW, SAPSQL or SAPPackage.
levelTrace, Debug, Info, Warn, Error or Fatal.
processId, threadIdProcess and thread that wrote the event.
sourceLogger, class or module that wrote the event.
requestId, clientSessionId, reloadId, appId, traceIdIdentifiers that correlate events across components with a Qlik Cloud reload.
messageMessage text, including any following lines of a multi-line entry.
file, lineLog file name and line number where the event starts.

Loading Gateway Logs into Qlik Cloud

Qlik Cloud apps can load gateway logs from the Monitor through the same Direct Access gateway, using the REST connector.

  1. By default, the gateway's REST connector does not allow connections to localhost. To allow them, add the line below to the C:\ProgramData\Qlik\Gateway\configuration.properties file (or change the existing value to true), then restart the Qlik Data Gateway - Direct Access Windows service.
  1. In Qlik Cloud, create a new data connection, select REST under your Direct Access gateway, and enter the following settings:
    • URL: http://localhost:5051/logs?start=YYYY-MM-DD, with a recent date. Use localhost, not 127.0.0.1, as the Monitor only accepts requests addressed to localhost.
    • Method: GET
    • Pagination type: Offset, with 'Start' parameter name offset, Start value 0, 'Count' parameter name limit and Count value 10000. The connector requests pages until a page returns fewer events than the count value.
  2. Load the data with a script like the one below. WITH CONNECTION replaces the URL of the connection, so the period and filters can be set at reload time.
  • Specify both start and end when paging, so that events logged while the app reloads do not shift the pages.
  • Each page reads the gateway logs from start, so use the shortest period and the most specific filters that meet your needs.

LogUploader

  • The automatic log collection and upload to FileCloud feature is designed to ensure continuous log coverage is available to Qlik Product Support and streamline diagnostics during a case. To enable the feature, add a LogUploader subsection under the Tasks section in the C:\ProgramData\Qlik\Gateway\Monitor\appsettings.json file. Create the file and sections as needed. Example shown below.

  • Schedule is a standard cron expression. The example below, 0 9 * * *, means collect logs every day at 9 AM. Use 24-hour time representation, ex. 3PM server time would be 15.

  • UploadUrl is the FileCloud upload share URL that we provide to customers when a SalesForce case is opened. Please note the following restrictions:

    • Only FileCloud links starting with https://files.qlik.com/url/ are supported.
    • If you set this URL to a manually-created, private shared folder, then it must have Upload-only permissions.
    • Other configurations and upload targets, ex. SharePoint, a local folder or fileshare, are not supported.

  • Days controls how many days the Monitor includes in each package. If the AutoSetNextStart setting is true, it only applies when the Monitor cannot find a recent successful upload in the C:\ProgramData\Qlik\Gateway\Monitor\tasks.db database. If the Days setting is not included in the appsettings.json file, then its value defaults to 3.

    • For example, if the Monitor runs at 09:05 local-server-time on 2024-01-03 with the setting "Days": 2, then it would include files and log events created or modified between 2024-01-01 00:00 and 2024-01-01 09:10.

  • AutoSetNextStart (default false): when true, each package starts at the time of the previous successful upload instead of going back Days days.

  • ChunkSize (default 20000000): the size in bytes of the chunks that the log package is split into for upload. Each chunk is posted separately, so only one chunk is held in memory at a time. If any chunk fails to upload, the upload fails and the error is written to the Monitor log.

  • Settings can be changed by editing and saving the file with any text editor. Restarting the service is not required.

  • To confirm that settings have been applied, open the latest C:\ProgramData\Qlik\Gateway\Monitor\Logs\monitor_YYYYMMDD.log file and look for an entry like: [INF] (Qlik.ConnectorAgent.Monitor) Logs will be automically uploaded to https://files.qlik.com/url/-redacted- at 03:00 PM

  • LogUploader settings can be changed at any time via a text editor and those settings will be applied on-the-fly (without restarting its Windows service).

Crash Dumps

  • The Monitor can configure Windows Error Reporting (WER) to save a crash dump when a Direct Access gateway process terminates unexpectedly. This replaces the Enable-DAG-Crash-Dumps.ps1 script. The feature is off by default and is intended to be enabled during a support case. To enable it, add a CrashDumps section to the C:\ProgramData\Qlik\Gateway\Monitor\appsettings.json file. Example shown below.
  • Optional settings:
    • Processes: executable names to capture dumps for. Defaults to ConnectorAgent.exe, dcaas.exe, MetricsCollector.exe and dotnet.exe. Note: dotnet.exe also applies to any other .NET application hosted by dotnet.exe on the server.
    • DumpType: Full (default) or Mini. Full dumps include process memory and can be several GB each.
    • DumpCount: maximum number of dumps kept per process. Defaults to 10.
    • MaxFolderSizeMB: maximum total size of these dumps. The oldest dumps are deleted first. Defaults to 20480 (20 GB), and 0 means no limit.
  • Dumps are saved to C:\ProgramData\Qlik\Gateway\Monitor\Dumps and are included in log packages.
  • CrashDumps settings are applied on-the-fly (without restarting its Windows service). Setting Enabled to false removes the WER settings the Monitor created, including those created by the Enable-DAG-Crash-Dumps.ps1 script. WER settings for these processes that were created by other tools and point to a different folder are left unchanged.
